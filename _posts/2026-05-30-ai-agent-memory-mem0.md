Mem0（一个开源的 agent 记忆库）发了份《2026 AI Agent 记忆现状》，把这件事讲得挺系统。我挑重点说，数字部分先打个预防针：那是他们自家的测评。

先讲为什么不能全塞进去。一段长对话动不动两万六千个 token 全喂给模型，问题有三个：一是贵，token 烧得心疼；二是慢，每轮都要重读整段历史；三是「中间被忽略」——关键信息埋在长上下文里，模型经常直接看漏。

真正的「记忆」是另一套打法：把对话里的事实抽出来，存进一个带索引的库，回答前只检索相关的那几条，还按用户、agent、会话分开隔离。说白了，记忆变成了一个独立的架构组件——有自己的 benchmark、自己的研究文献，而不再是「写一个更长的 prompt」。

数字上，Mem0 自家算法报的成绩是：LoCoMo 拿 92.5 分，但每次查询只用约 6956 个 token——全上下文那套要两万六，等于把 token 省到了 1/26。跟他们上一代比，时间推理 +29.6 分、多跳推理 +23.1 分。这里我得说清楚：对比的是他们自己 2025 年的版本，不是第三方标准，目前也还没有独立复现。当思路记，别当定论。

检索那一层也挺有意思：存的时候一次性把实体和事实抽出来；查的时候三路并行打分——语义相似、关键词、实体匹配——再融合成一个排序。实体匹配直接内建，省掉了过去要外挂的图数据库。

评测也开始标准化了，这点比单个数字更值得关注：LoCoMo（1540 题）、LongMemEval（500 题）、还有 BEAM（百万到千万 token 的生产级压力测试）。生态上 Mem0 已经接了 21 个框架、20 个向量库。

说实在的，数字是厂商自报，别全信。但那个判断方向是对的、也最该带走：agent 想长期可用，记忆不能靠「把历史全背下来」，得学会「抽重点、按需取」——这跟人记事，本来就是一个道理。

你在做 agent 的时候，是把全部历史一股脑塞进上下文，还是给它配了一套真正的「记忆」？
