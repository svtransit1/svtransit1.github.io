阿里在 5 月 20 号的云栖大会上发了 Qwen3.7-Max。先把分数说完:它在 Artificial Analysis 的智能指数上拿到 56.6,全球排第五,是这张榜上排名最高的中国模型,比上一代 Qwen3.6-Max-Preview 涨了 4.8 分。第五意味着前面还有四个,差距没抹平;但对一个中国模型来说,这已经是离顶尖最近的一次。只是,真正值得说的,是另一件事。

放进大盘里看更清楚。智能指数前面那四个,基本就是 GPT、Claude、Gemini 这条西方前沿线;一个中国模型挤进全球前五,这两年还是头一回贴得这么近。但阿里这次显然不想把故事讲成「我们跑分追上来了」——它把聚光灯,直接打到了那 35 个小时上。

阿里给的招牌演示,不是答一道难题,是让 Qwen3.7-Max 自己跑。连续、自主运行 35 个小时,中途调用了 1158 次工具,做了 432 轮 kernel 评估——它在干的活,是给阿里自家的新芯片优化底层 kernel。35 小时、上千次工具调用、一条始终没断的推理链。

这就是「Agent 时代的模型」这句话,落到地上的样子。过去比模型,比的是「单轮答得多准」——一道题、一个 benchmark 分。可 agent 真正吃的是另一种能力:把一条又长又绕的任务,从头到尾撑住——不在第十个小时崩掉,不在第八百次工具调用之后忘了自己在干嘛。前沿的标尺,正在从「每一轮有多聪明」,慢慢挪向「能独立撑多久」。

具体一点说,这件事为什么要紧。你真正想交给 agent 的活,很少是五分钟能跑完的——一次跨十几个文件的重构、一轮要反复试错的调参、一段从查资料到出结论的研究。这些任务过去的拦路虎,往往不是模型「不够聪明」,而是它跑着跑着就丢了线索:忘了最初的目标、把前面刚定的结论又推翻、在某次工具调用之后开始原地打转。35 小时不断、432 轮 kernel 评估一轮接一轮,说明的正是它能稳得住——这恰恰是把 agent 真正放出去单干时,最缺的那一块。

配套的两件事也指向同一个方向。一是上下文窗口,从上一代的 256K 直接拉到了一百万 token——任务跑得越长,中途堆起来的状态越多,窗口就越得够大,这两件事是绑在一起的。二是它支持外部 harness,比如 Anthropic 的 Claude Code:你不用为它换掉整套 agent 框架,可以直接把 Qwen3.7-Max 塞进你已经在用的工具里跑。能不能「无痛接入」,正在成为模型之间一个新的竞争点。

从定位上看,阿里的意图也很清楚:Qwen3.7-Max 主打编码 agent,从前端原型一直到跨多文件的复杂工程;同时通过 MCP 接各种工具,也能当办公和生产力助手。换句话说,它不是用来陪聊的——是冲着「替你把活干完」去的。

还有一层:Qwen3.7-Max 不是单独发的。它和阿里自研的震武 M890 加速芯片、磐久服务器一起,被打包成一套「AI 工厂」式的全栈;模型在那 35 小时里优化的 kernel,跑的就是阿里自己的芯片。模型、芯片、服务器,阿里想把这一整条链都攥在手里——大厂不再满足于只做模型。

但有件事和 Qwen 过去的形象不一样:Qwen3.7-Max 这次是闭源的,目前只有 API 预览,没放出开源权重。Qwen 这个名字这两年很大程度上是靠一串开源模型攒起来的;旗舰转向闭源,等于把最强的那一档,从「谁都能下载来跑」收成了「只能调我的接口」。这个转弯,值得记一笔。另外提醒一句:那个「35 小时」来自阿里自己的内部测试,不是第三方复现,看的时候心里要有数。

就算把这些都打个折,信号依然清楚。当一家公司把「我的模型能自己跑 35 小时」拿出来当头条,而不再是「我又多拿了几个 benchmark 分」——你能感觉到,这个行业真正在意的东西,正在换。对天天在用 agent 的人来说,这其实是好消息:你最头疼的从来不是模型答得不够漂亮,而是它在长任务里中途掉链子。各家开始正面拼「续航」,受益的就是你手里那些一跑就是几个钟头的活。下次再看到一个新模型,别只盯着它的跑分——多问一句:它能独立撑多久?这个答案,正在变得比分数更重要。
